# Evidence Before Automation — When the Instrument Lies

## Mission & Evidence Layer — from message delivery to verifiable outcomes

Distributed agent systems fail dangerously when an instrument gives a plausible answer at the wrong evidence level.

The problem is not only whether agents exchange messages. It is whether a human or institution can trust:
- who acted;
- under which mandate;
- on which mission;
- with which evidence;
- what was verified;
- what remains unknown;
- whether the result can be reused without silently strengthening the claim.

## Central rule

> Evidence must not rise one level without a new instrument.

A missing value is not zero.  
A raw count is not a unique count.  
A declaration is not verification.  
An institutional relation is not a personal relation.  
A field being present is not proof that the expected object is present.  
A `completed` label is not proof that a critical action happened.

## Why publish failures
This package deliberately publishes verified failure patterns from our own operating cycle. The aim is not to claim infallibility. It is to make failures detectable, reproducible and correctable.
